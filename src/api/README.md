# Статический каталог PRICE-01 (текущая подготовка)

Текущий вход — `data/catalog/reference/S1-06-price-v1/release-manifest.json`: catalog-v2, D06-price-v2, reference-price-v1, один PriceSet. Подготовлены10 новых recipeRef,32 исторических наблюдения и29 оценок. Производственного ресурса ещё нет: необходимы10 окончательных D06 и независимое принятие точной версии набора. Самопроверки/шаблоны не заменяют акты; прежний accepted S1-05 сохраняется историческим.

```powershell
python -X utf8 checks/S1-06/verify.py
python -X utf8 checks/S1-06/document_handoff.py
python -X utf8 checks/S1-06/assemble_catalog.py
python -X utf8 checks/S1-06/assemble_catalog.py --write
```

Нужен рабочий Python3.11+; фактический путь bundled Python этой среды указан в checks/S1-06/README.md. До актов последние команды ожидаемо дают exit1 без production. После актов assembler независимо проверяет registry, точные refs/версии, весь граф, методы/происхождение/упаковки, D06 и PriceSetReview; затем назначает фактические publishedAt и локальный Europe/Moscow publishedOn. Наблюдение, оценка, проверка и решение сохраняют свои даты. Старые акция/слот/остаток/минимум магазина и возраст>30 дней не блокируют справочный расчёт.

Ресурс `public/catalog/<catalogVersion>/`: snapshot.json, resource-manifest.json (SHA каждого payload/evidence/image, schema/policy/priceSetRef/digest и раздельные даты), все Source.capturedEvidence.locator и image.locator, карта переноса, реестр и точные финальные акты. Сначала staging, повторный SHA/JSON-контроль, затем одно переименование. Версию нельзя перезаписать; повторный выпуск требует новой catalogVersion. Локальная сборка не означает сетевое размещение. sourceFiles карты описывает архив исходных материалов проекта, а не дополнительные сетевые зависимости runtime.

Будущий `api.loadCatalog(catalogVersion)` должен:

1. Получить manifest безопасной версии относительно import.meta.env.BASE_URL и проверить schema/version/policy/priceSetRef.
2. Проверить SHA байтов snapshot и всех нужных evidence из той же версии; не смешивать пути разных публикаций.
3. Декодировать целый catalog-v2, точные refs, один набор, его accepted-review, все выбранные оценки/наблюдения и D06. Только целый проверенный граф означает loaded; ошибка означает unavailable без частичного каталога.
4. Разрешать capturedEvidence.locator/image.locator относительно корня ресурса выбранной версии. Проверка SHA выявляет повреждение, но не заменяет семантическую валидацию и приёмку.

Этот runtime-адаптер и codec пока не реализованы. Данные не подключены к пользовательским экранам. Домен/генератор/Worker/guest storage здесь не добавлялись. Транспорт подтверждён настоящим localhost HTTP только во временных TEST-ресурсах: две публикации с неизменным набором,142 файла с SHA,404 и отказ перезаписи.

[Проверки](../../checks/S1-06/README.md), [пакет для лида](../../data/catalog/reference/S1-06-price-v1/README.md). Ниже сохранено описание прежнего v1-процесса; его требования текущего магазинного контекста относятся к историческому режиму. Команды legacy запускаются с --mode legacy.

# Каталог и API

В S1 слой `api` получает неизменяемый статический `CatalogSnapshotDTO`; в S2 источник меняется на Firestore с сохранением контракта. UI и домен не читают кандидатов напрямую.

Подготовлены десять полных пакетов: принятая S1-05 и девять новых на проверку лида. Вход сборки — `data/catalog/candidates/S1-06/release-manifest.json`. Самопроверки исполнителя не являются окончательными reviews. До девяти реальных решений лида сборка ожидаемо отказывает с exit 1 и не создаёт производственный ресурс.

После решений лида и обновления применимости цен:

```powershell
python -X utf8 checks/S1-06/verify.py
python -X utf8 checks/S1-06/document_handoff.py
python -X utf8 checks/S1-06/assemble_catalog.py
python -X utf8 checks/S1-06/assemble_catalog.py --write
```

Сборщик проверяет весь набор, реестр, версии, ссылки, окончательные reviews, числа и ценовой контекст. В `public/catalog/<catalogVersion>/` создаются `snapshot.json`, `resource-manifest.json` с SHA-256 каждого файла и локальные свидетельства/заглушка. Каталог собирается во временном соседнем каталоге и переименовывается в конечный путь. Существующая версия не перезаписывается. Это локальная сборка, не развёртывание.

Аудит кандидатов проходит при0…9 новых решениях: читает и проверяет каждый существующий final review, а отсутствующие показывает как незавершённый допуск. Производственный preflight проходит только при всех принятых точных версиях и применимых ценах. rejected/waiting_rule, самопроверка и неверные версии отклоняются. После добавления решения не требуется заново строить данные: это могло бы сменить проверяемое основание. Регрессия всех переходов — `checks/S1-06/verify_review_progress.py`; её фикстуры временные, не реальные акты.

Получение будущим адаптером `api.loadCatalog(catalogVersion)`:

1. Проверить безопасный формат версии. Получить `catalog/<catalogVersion>/resource-manifest.json` относительно `import.meta.env.BASE_URL`; проверить HTTP и совпадение версии.
2. Получить байты `snapshot.json` из той же версии; проверить SHA-256 до JSON-декодирования. Хеш выявляет повреждение, но не заменяет проверку модели и приёмки.
3. Проверить весь `catalog-v1`: поля, точные версии и замкнутость ссылок, уникальность ID, окончательные reviews, форматы чисел, единицы и применимость оснований. Только после полной проверки вернуть `loaded(snapshot)`; при сбое — `unavailable(reasons)` без частичного каталога.
4. Локаторы `capturedEvidence.locator` и `image.locator` разрешать относительно корня **ресурса этой версии**, а не корня сайта. Их файлы перечислены в манифесте. Не переписывать локаторы внутри DTO.

`checks/S1-06/verify_static_delivery.py` проверяет упаковку и HTTP-доставку принятой S1-05 во временной директории: 16 файлов, равенство снимка, версия, все SHA, HTTP 404 и запрет перезаписи версии. Фикстура не попадает в `public/` и не выдаётся за выпуск десяти принятых рецептов.

Полный runtime-декодер, адаптер `loadCatalog` и его подключение к экрану здесь ещё не реализованы. Offline-аудит и проверка транспорта не заменяют эту будущую интеграцию. Генератор и расчётные модули не добавлялись.
