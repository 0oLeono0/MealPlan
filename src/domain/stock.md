# Расчёт покрытия запасами S1-10

`calculateStock(demand: MenuDemand, source: StockSource,
translations?: readonly StockTranslation[]): StockCalculation` — чистая функция
из `stock.ts`. Принимает готовый результат `aggregateDemand` S1-09 одного варианта.
Не масштабирует рецепты, не использует прежние дефициты/остатки и не читает общий
склад, UI, часы, каталог или хранилище. Все вычисления — `Rational`, без округления.

## Разрешённый источник

`StockSource` — числовая проекция `FrozenStockSourceDTO` (§13.8 архитектуры):

- `mode: none`, `selectedGroupIds: []`, `groups: []` — запасы исключены.
- `mode: selected` — непустой уникальный список ID и ровно одна запись состояния
  каждого ID: `{kind: present, group}` либо `{kind: absent, stockGroupId}`.
  Отсутствующая ранее выбранная группа — подтверждённое отсутствие, не старый запас.
  Невключённые группы передавать нельзя; функция отклоняет такой источник.

`StockGroup`: `stockGroupId`, `groupVersion`, разрешённые `productRef`, `stateRef`,
`basis: QuantityBasis | null`, `entries`. В этой проекции принадлежность продукта
и состояния задаёт группа; поле stateRef каждой записи полного DTO проверяет
адаптер до вызова. Основания известных записей и unitHint должны соответствовать
группе. Простые разные единицы одной размерности допустимы внутри группы;
непереводимые основания передаются отдельными группами. Межразмерный перевод
выбранных групп выполняется при сопоставлении потребности, не при вводе запасов.

`groupVersion` — каноническая строка целого ≥ 0 по §13.1: `"0"` допустима,
ведущие нули, знак, дробь и пробелы недопустимы. Строка сохраняется без перевода
в `number`, включая большие версии. Каталожная `recordVersion` отдельно остаётся
канонической строкой положительного целого.

`StockEntry`: уникальный во всём источнике `stockEntryId`, `urgent`, `quantity`:

- `{kind: known, value: Quantity}` — неотрицательное исходное пользовательское
  количество с шагом `validateQuantity(..., 'stock')`.
- `{kind: unknown, reasons: [StockUnknownReason, ...], unitHint?: QuantityBasis}` —
  без числа. Причина проекции содержит `code` и `explanation`; адаптер сохраняет
  полный исходный ReasonDTO в замороженном входе. Hint сохраняет намерение ввода,
  но не доказывает числовую несовместимость неизвестной записи с потребностью.
  Без hint у unknown нет придуманного основания.

Дубли ID записей/групп отклоняются. Новая физическая часть должна иметь новый ID;
смена единицы той же записи заменяет её представление, не добавляет запись.
`urgent` сохраняется в выходном снимке и не участвует в арифметике/очереди покрытия.
Digest, происхождение, timestamps, перенос/уточнение/замена записей и проверка
актуальности исходного снимка остаются у вызывающего слоя; здесь они не вычисляются.

## Совместимость и переводы

Прямое сопоставление использует `convertQuantity`: точные productRef/stateRef,
размерности и определения конкретных штук. Названия не используются.
Для каждого необходимого перехода вызывающий слой может передать
`{stockEntryId, demandKey, steps}`. Это одна выбранная цепочка `ConversionStep`;
все её коэффициенты, условия, направления и диапазоны проверяет существующий
конвертер. Поиска пути, выбора между свидетельствами и обратного коэффициента
по умолчанию нет. Повтор пары entry/target отклоняется.

Цепочка нужна только при отсутствии прямой совместимости. Непустая цепочка
напрямую совместимого запаса отклоняется `REDUNDANT_STOCK_TRANSLATION`, чтобы
коэффициент не менял/скрывал обязательный учёт этого количества.
Отказ нужного перевода не уничтожает известное исходное количество:
`incompatibleEntries` содержит entry/group IDs, `original`, `attemptedSteps` и
причины конвертера (`CONVERSION_MISSING`/`STOCK_STATE_INCOMPATIBLE`).

Общая совместимая потребность уже должна быть объединена S1-09 на выбранном общем
основании. Вызывающий слой разрешает основания и согласованные цепочки до этой
агрегации. Одна запись может иметь только одну успешную цель внутри варианта.
Если она напрямую или по переданным цепочкам подходит нескольким строкам,
функция отклоняет вход `AMBIGUOUS_STOCK_TARGET`: не удваивает запас и не выбирает
произвольный приоритет строк. Например, одна штука с цепочками в 50 г и 100 мл
не становится двумя независимыми запасами для двух необъединённых потребностей.
Такой вход требует согласованного общего основания потребности/переводов на
границе разрешения. Сам калькулятор не меняет принятую потребность S1-09.

Неизвестность относится ко всем потребностям того же точного продукта/состояния,
включая случай без hint или с hint непереводимого основания. Неизвестность другого
продукта/состояния/версии не блокирует строку. Числового перехода неизвестной
записи между состояниями нет.

## Выход и доступность

`StockCalculation` сохраняет `planId`, `variantId`, отдельный глубоко замороженный
снимок `source` (включая посторонние unknown) и `lines`. Каждая `StockDemandLine`
сохраняет исходные `key`, `required`, `contributions` S1-09 и добавляет:

| Поле | Соответствие числовой части DemandLineDTO (§13.7) |
| --- | --- |
| `knownStock` | Sknown: сумма успешно переведённых известных записей |
| `usedKnown` | uKnown = min(Sknown, R) |
| `knownLeftover` | Sknown − uKnown; только остаток известной совместимой части |
| `stockTotal`, `usedTotal`, `deficit`, `leftover` | available Quantity либо unavailable с непустыми reasons |
| `sourceEntryIds` | Уникальные IDs совместимых известных и относящихся unknown записей |
| `unknownEntryIds` | Влияющая неизвестность продукта/состояния |
| `knownEntries` | IDs записи/группы, исходное и приведённое количество, применённая цепочка |
| `incompatibleEntries` | Известные записи того же продукта с причиной отказа для этой строки |
| `slots` | Объединённые потребности слотов, aKnown, uncoveredKnown и исходные вклады с aKnown |

При отсутствии unknown: u=min(S,R), d=R−u, ℓ=S−u.
При unknown и Sknown<R: доступны только известные покрытия, окончательные
stockTotal/u/d/ℓ unavailable(`STOCK_QUANTITY_REQUIRED`). В причине сохранены
влияющие entry IDs, R и Sknown. `uncoveredKnown` не является окончательным d.
При unknown и Sknown≥R: u=R, d=0 доступны; stockTotal/ℓ недоступны,
knownLeftover показывается отдельно. При none разрешённый числовой источник пуст:
u=0, d=R, stockTotal=0 относится только к этому пустому источнику;
leftover unavailable(`STOCK_SOURCE_EXCLUDED`) и не прогнозирует общие запасы.

Строки упорядочены по `demandKey`, IDs записей — по UTF-16. Покрытие идёт по
возрастанию `DemandContribution.order`, с предварительной суммой всех совместимых
вкладов одного slotId. S1 передаёт breakfast/lunch/dinner/snack как 0…3;
для нескольких дней вызывающий слой обязан передать глобальный порядок:
сначала день, затем слот. Отображение/фильтрация не задают очередь расчёта.
Внутри слота объяснительное aKnown распределено по ingredientId (UTF-16), без
повторного масштабирования; суммы вкладов равны покрытию объединённого слота.

Функция проверяет согласованность R с сохранёнными вкладами, ключами и порядками,
но не заменяет валидацию полного DTO/каталога/допустимости меню. Некорректные
разрешённые проекции отклоняются исключением; бизнес-неполнота количеств является
успешным результатом с unavailable. Пустая потребность даёт пустые строки;
отсутствие потребности не уточняет посторонние неизвестные количества.

`key` остаётся ключом S1-09, не `demandLineId`. Будущий адаптер строит ID с
namespace и CanonicalJSON-v1 `[planId, variantId, stateId, basisId]`, кодирует
Rational/основания/причины и сопоставляет slots.contributions с вкладами DTO.
Цена/priceSelectionRef, приобретение, упаковки, бюджет и полный codec относятся
к следующим задачам. Для S1-11 пригоден только `deficit.kind === available`;
`uncoveredKnown` и `knownLeftover` не заменяют окончательные результаты.

Каждый повтор/вариант рассчитывается отдельным вызовом из исходного source.
Ни выходной остаток, ни покрытие другого варианта не являются новым источником.
Функция не изменяет и не замораживает входные объекты.
