# Допустимость рецепта S1-12 / DIET-v1

`checkRecipeEligibility(input: RecipeEligibilityInput): RecipeEligibility` из
`eligibility.ts` проверяет один рецепт для конкретных типа приёма пищи, H/M,
даты, лимита времени и набора диет. Чистая функция: без часов, сети, React,
хранения, генератора, поиска свидетельств и изменения входов. КБЖУ, количества
ингредиентов, стоимость и бюджет не пересчитываются. Предпочтения «Не люблю»,
разнообразие и использование запасов не входят в этот API и не создают запретов.

## Граница с каталогом

Это **разрешённая семантическая проекция**, не полный DTO/codec. Смысл свободного
текста состава/сертификата код не извлекает. Адаптер обязан разрешить и проверить
сохранённые первичные основания, затем явно передать факты. Нельзя преобразовать
`DietAssessmentDTO.status=confirmed` или тег в факт соответствия.

| Поле | Разрешение / соответствие DTO |
| --- | --- |
| `recipe.recipeRef` | Точная версия RecipeDTO; без поиска по названию |
| `processRef` | Версия проверенного процесса. В текущем каталоге это recipeRef: состав и шаги неизменяемы в пределах версии. Отдельной новой коллекции процессов не требуется |
| `baseServings` | Собственное B, Rational > 0 с конечным десятичным представлением; null — допустимая неполнота. Источник/нормализацию B проверяет D06-06, здесь нет нового приведения «на порцию» |
| `ingredients` | Каждая исходная ingredientId с точными productRef/stateRef и compositionRef. Для существующих specific_goods compositionRef может быть productRef: его версия фиксирует полный состав. Состояние проверяется отдельно. facility — точная площадка или null, не придуманное название |
| `mealTypes`, `mealTypeRecipeRef`, `mealTypeEvidenceRefs` | Только явно разрешённые проверяющим типы, версия рецепта и сохранённые SourceDTO. Нет автоматического расширения списка |
| `review`, `imageKind` | Проверенная проекция D06ReviewDTO на ту же recipeRef, D06-price-v2. Все D06-01…10 и 14…16 должны присутствовать с источниками. D06-11/12/13 проверяются заново ниже. Допустим passed; not_applicable только D06-16. Заглушка S1 требует accepted_with_placeholder и пройденного D06-15 |
| `sources` | Точные ref/kind, сохранённый непустой fragment, checkedOn/By. Полные locator/capturedOn/права/источники остаются в исходном замороженном каталоге |
| `evidence` | Структурированные DietFactEvidence с DIET-v1, областью, checkedOn/By, sourceRefs и warnings. Связи задаются ingredient.evidenceRefs и processEvidenceRefs. Модуль не выбирает удобный источник из каталога |
| `timeEvidence` | CookingTimeEvidence S1-07 с точными Rational границами, плюс recipeRef/processRef, method, includesWaiting, conditionsConfirmed, checkedOn/By. Длительность уже полная, с ожиданием |
| `evaluationDate` | Явная реально существующая YYYY-MM-DD; источники/оценки из будущего не применяются. Часы не читаются |
| `people`, `multiplier`, `cookLimit` | H=1…10; M=1/2, 1, 2 (по умолчанию 1, в S1 вызывающий слой передаёт 1); any либо точный положительный maxMinutes. Ограничение пользовательского выбора 15/30/60 проверяет форма/адаптер |

Для элемента RecipeDTO.timeEvidence нет отдельной каталожной коллекции:
его ref — устойчивый локальный дескриптор проекции, например namespace +
CanonicalJSON `[recipeId,index]` и recordVersion рецепта. Не следует искать такой
дескриптор в dietEvidence. Диапазон DecimalText разбирается существующим точным
парсером; derivedRange с RationalDTO разрешается без округления в десятичную строку.

До вызова адаптер дополнительно проверяет:

1. Полный поддерживаемый catalog-v2, целостность ссылок/версий, принятие D06,
   соответствие recipe/review/ingredients/states/products/bases и всех исходных
   полей. D06 проецируется после проверки фактического наличия количества,
   нутриентов, методик, шагов, изображения/прав и ценового основания. Passed без
   источника недостаточен; копирование только решения review не является проверкой.
   Числовые/денежные проверки выполняют существующие модули, а не eligibility.
2. Смысл состава и происхождение спорных компонентов; отсутствие добавок для
   цельного продукта; что заявление относится к точному товару/версии состава,
   а не бренду вообще. Все смеси, соусы, ферменты и желатины должны быть раскрыты.
   Неопределённое происхождение нельзя проецировать как доказанное отсутствие.
3. Для процесса — все существенные шаги и добавки, условия, версию и область
   масштаба. `conditionsConfirmed` выставляется после проверки сохранённых
   условий. scaleRange=null означает отсутствие ограничения масштаба **в этом
   проверенном основании**, а не автоматическое обобщение локального измерения.
4. Для сертификата — сохранённый документ и проверку именно его номера,
   срока, товара и площадки у выдавшей организации. `confirmed_by_issuer`
   означает выполненную проверку по связанному certificate_issuer SourceDTO,
   не чтение логотипа. Модуль не обращается к IFANCA и не аутентифицирует документ.
5. Сохранить полный исходный DTO/замыкание/права/фрагменты, provenance, исходные
   DietAssessmentDTO с причинами и дату/проверяющего. Числовая проекция не заменяет
   каталог и его digest/freshness. При изменении состава/процесса обновить ссылки
   и перепроверить факты; новая цена неизменного продукта сама не меняет факты.

## Факты и применение DIET-v1

`IngredientFact` содержит один проверенный вид знания:

- identity: свежие цельные фрукты/овощи, прочие свежие цельные растения,
  чистая вода или соль, с явным noAdditives;
- composition: полнота списка и present/absent/unknown для fish, gluten,
  milk, lactose, non_vegetarian, haram. Пропущенное свойство — unknown.
  non_vegetarian включает мясо/птицу/рыбу/морепродукты, животный желатин,
  убойные жиры и животный сычужный фермент. haram включает свинину/производные,
  кровь, алкогольные напитки и добавляемый алкоголь;
- manufacturer_claim: явное gluten_free/lactose_free/vegetarian заявление
  либо его противоречие, с обязательным применимым источником manufacturer;
- trace: сохранённое предупреждение о возможных следах;
- conflict: явно зафиксированный неразрешённый конфликт конкретных фильтров;
- certificate: номер, issuer, inclusive validFrom/Through, coveredGoods,
  facility, processRef, подтверждение условий обработки и проверки у организации.

Это факты текущего конкретного продукта/состояния/состава; их нельзя подменять
исходной рекламной строкой. Например, milk=present не означает lactose=present:
обычное молоко без заявления даёт unknown, явно добавленная лактоза — violated.
«Низколактозный» не проецируется как lactose_free. Неуточнённый фермент означает
non_vegetarian=unknown; его нельзя объявить животным или микробным по догадке.

| Диета | Подтверждение при полном основании; доказанное нарушение |
| --- | --- |
| no_fish | Разрешённая цельная растительная идентичность/вода/соль либо полный состав с fish=absent. fish=present нарушает. Морепродукты без рыбы этим полем не исключаются |
| gluten_free | Для свежих цельных фруктов/овощей, воды/соли — идентичность. Для прочих, включая крупы/специи/прочие растения, — полное основание и явное заявление производителя. gluten=present нарушает; следы глютена блокируют положительный статус |
| lactose_free | Цельная немолочная идентичность либо полный состав с milk=absent; при молочном/спорном компоненте нужно явное заявление lactose_free. lactose=present нарушает. Молочные белки и возможные следы не объявляются исчезнувшими |
| vegetarian | Разрешённая цельная растительная идентичность/вода/соль либо полный состав и non_vegetarian=absent/применимая маркировка производителя. non_vegetarian=present нарушает; лакто-ово допускает молоко, яйца и мёд |
| halal | Разрешённая свежая цельная растительная идентичность/вода/соль; для прочего — полное основание и действующий IFANCA на точный товар/площадку с проверкой у организации и соблюдением процесса. haram=present нарушает независимо от другого положительного статуса |

Каждому фильтру дополнительно нужен применимый process-факт: точные
recipeRef/processRef, подтверждённые условия, подходящий scaleRange и
сохранённый источник. В process-факте outcome означает проверенный состав
и обработку, а не итог всего рецепта. Итог вычисляется заново по всем ингредиентам
и процессу: доказанное нарушение имеет приоритет, иначе недостающий факт,
конфликт, неподтверждённое происхождение или неприменимость дают unknown.

Одновременно present и absent для одного свойства либо confirmed и violated
для одного процесса дают EVIDENCE_CONFLICT: спорный факт не является доказанным
нарушением. Отдельное бесспорное нарушение другого ингредиента сохраняет
violated. Положительные/отрицательные заявления производителя проверяются
и при выводе из состава/идентичности, чтобы конфликт не скрывался коротким путём.
Следы рыбы — предупреждение, а не намеренный рыбный ингредиент. Остальные
предупреждения сохраняются; медицинская безопасность/сертификация дома не выводятся.

## Время, допуск и выход

Только k вычисляется как H×M/B. `inExactRange` проверяет его до округления,
учитывая открытые/закрытые концы. Длительность не умножается на k. При отсутствии
полного применимого времени — unconfirmed, включая any. Если применимые полные
оценки расходятся, totalMinutes=null и EVIDENCE_CONFLICT; выбор меньшего числа
запрещён. При одинаковых значениях сохраняются все основания. Полное время ровно
на лимите допустимо; превышение даёт violated/TIME_LIMIT_EXCEEDED с точными
actual/maxMinutes. Any снимает только численное ограничение.

`RecipeEligibility` содержит basis (отделённый снимок всего входа), отдельные
data/mealType/time проверки, factor/totalMinutes и **ровно пять** dietAssessments
в порядке DIETS. Каждая оценка сохраняет ingredientAssessments, process,
рассмотренные/применимые ссылки, причины, warnings и requiredGoodsRequirements.
Дата/проверяющие исходных фактов остаются в basis; evaluationDate — дата проверки,
а не дата нового наблюдения. Неприменимые/истёкшие сертификаты сохраняются в basis,
но не входят в certificateRefs требований к покупке.

Итог assessment: violated при доказанном нарушении любого выбранного обязательного
условия; иначе unconfirmed при неизвестности обязательного условия; confirmed
только при полном подтверждении. `eligible` равен assessment.kind===confirmed.
Невыбранные диеты не участвуют в допуске, но их все пять оценок/причин сохранены.
Это ещё не допуск меню: бюджет/КБЖУ и прочие ограничения проверяет следующий слой.
NO_RECIPES_FOR_SLOT здесь объясняет исключение **этого рецепта** по типу и не
доказывает отсутствия всех рецептов/всего меню.

Верхний requiredGoodsRequirements содержит требования только выбранных диет;
в каждой оценке сохранены её собственные требования, включая неизвестные.
Каждое требование связывает ingredientId с product/state/composition,
facility, нужным kind, evidenceRefs и применимыми certificateRefs. Номер/срок/
область документа разрешаются по этим ссылкам в basis.evidence; не следует
заменять товар похожим и наследовать статус. Адаптер передаёт требования в
AutomaticShoppingLineDTO и кодирует Rational/reasons в DTO.

Выход глубоко заморожен и отделён от входа; Rational уже неизменяем.
Вход не изменяется и не замораживается. Повторы с тем же входом воспроизводимы.
Отсутствующая/чужая версия названной ссылки — ELIGIBILITY_REFERENCE_MISSING;
дубликаты/некорректная числовая проекция — ELIGIBILITY_PAYLOAD_INVALID;
чужая политика — ELIGIBILITY_VERSION_UNSUPPORTED. Адаптер сопоставляет их с
REFERENCE_MISSING, PAYLOAD_INVALID/SNAPSHOT_CORRUPT и VERSION_UNSUPPORTED.
Корректная нехватка доказательства передаётся пустыми связями/unknown-фактами,
а не висячей ссылкой. Неизвестность возвращается успешным результатом с причинами.

## Проверки и пределы

`eligibility.test.ts` воспроизводит все 21 DT20 на явно обозначенных
синтетических семантических проекциях документальных фактов. Проверены
пересечения, замена товара/состава/состояния/процесса, потеря/конфликт оснований,
источники, сроки и область IFANCA, следы, точные пределы времени/k, any,
неверный тип, обязательные D06, заглушка, неизменность и повторы.
Положительные тестовые сертификаты вымышлены и не подтверждают реальные товары.

Отдельный тестовый мост разрешает опубликованную S1-05@2 и её источники,
используя явно записанную семантику DATA_SOURCES §5, а не saved status/поиск слов:
только snack, время 10 минут при k=1, no_fish/vegetarian confirmed,
GF/LF/halal unknown. Мост не является готовым codec. Текст исходной applicability
процесса упоминает recipe@1/исходный объём; адаптер теста использует принятое
соответствие @2 из D06 и точные subjectRefs при неизменных шагах, сохраняя k=1.
Для автоматического переноса других версий такое соответствие нельзя придумывать.

Не проверены новая реальная сертификация товаров, произвольный импорт каталога,
сквозной браузер/Worker/хранилище и существование меню для любого набора фильтров.
Свидетельства берутся из сохранённых материалов; нового сетевого поиска нет.
