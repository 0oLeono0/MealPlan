# Домен: точные числа, единицы и масштаб (S1-07)

Чистые правила §§5/13.1 ARCHITECTURE.md и S0-04/04a/05 REQUIREMENTS.md.
Без React, браузерных API, часов, сети, хранения и новых зависимостей.
Диагностический Worker остаётся отдельным протоколом.

## Публичный API

| Модуль | API | Назначение |
| --- | --- | --- |
| `rational.ts` | `Rational.of(n, d = 1n)`, `ZERO`, `ONE` | Неизменяемая сокращённая дробь, d > 0, ноль 0/1 |
| `Rational` | `add`, `sub`, `mul`, `div`, `neg`, `abs`, `compare`, `equals` | Точные операции и сравнение без epsilon |
| `Rational` | `trunc`, `floor`, `ceil`, `isInteger`, `isMultipleOf`, `isFiniteDecimal` | Целочисленные операции, кратность шага, конечность десятичной записи |
| `numberInput.ts` | `parseUserNumber(raw)`, `parseDecimalText(raw)` | Разбор непосредственно в BigInt; результат `valid/empty/invalid/technical_error`, исходный `raw` сохранён |
| `quantity.ts` | `validateQuantity(value, unit, usage)`, `isUnit`, `UNITS` | Знак ингредиента (>0) / запаса (≥0), единица, точная кратность шага |
| `quantity.ts` | `convertUnit(value, from, to)` | Только арифметика г↔кг и мл↔л. Эта функция не доказывает физическую совместимость |
| `conversion.ts` | `convertQuantity(original, target, steps = [])`, `normalizeQuantity(original, baseBasis)` | Проверка продукта, состояния, основания и выбранной подтверждённой цепочки; исходная величина сохраняется |
| `conversion.ts` | `inExactRange(value, range)` | Точные границы с явным включением концов |
| `recipeScale.ts` | `RecipeBaseline.fromSource(source)`, `scaleRecipe(baseline, people, multiplier = ONE)` | Однократное приведение источника на весь B; пересчёт из q⁰/N⁰ по H×M/B |
| `presentation.ts` | `roundHalfAwayFromZero`, `formatDecimal`, `formatQuantity`, `formatMoney`, `formatEnergy`, `formatMacronutrient`, `formatMoneySum` | Только представление; округление не изменяет исходное значение |

Основные типы: `NumberParseResult`, `Unit`, `Dimension`, `EntityRef`, `QuantityBasis`,
`Quantity`, `QuantityValidation`, `ExactRange`, `Conversion`, `ConversionStep`,
`ConversionResult`, `RecipeScaleSource`, `RecipeNutrition`, `ScaleIngredient`,
`CookingTimeEvidence`, `ScaledRecipe`. Импортировать из указанного модуля.
Числовой DTO и его граница находятся в `../codec/rational.ts`.

## Ввод и неизвестность

Пользовательский ввод допускает точку/запятую, ведущие/конечные нули, знак и
пробелы вокруг числа; строка сохраняется дословно. Требуются цифры с обеих сторон
разделителя, если он есть. Смешение разделителей, группировка тысяч, экспонента,
NaN/Infinity, дробь вида `1/3` и посторонний текст отклоняются.
`DecimalText` принимает только каноническую строку каталога, включая запрет `-0`,
плюса, пробелов и конечных нулей дробной части. Пустой DecimalText недопустим.

Разбор не задаёт ограничений величины. После успешного разбора количества
вызывается `validateQuantity`; цены/коэффициенты/КБЖУ не получают шаг количества.
Количество, полученное вычислением, повторно по шагу ввода не валидируется.
Неизвестность не является числом: владелец `KnowledgeDTO` сохраняет свою ветвь
`unknown/reasons` и не вызывает арифметику вместо отсутствующего значения.
Ни пустота, ни ошибка, ни отказ перевода не содержат подставленного нуля.

Самовольного лимита длины/точности нет. Перехватываемый `RangeError` при разборе
и декодировании DTO даёт `technical_error/RESOURCE_EXHAUSTED`, сохраняя ввод.
В точных операциях/форматировании ресурсный `RangeError` распространяется вызывающему
слою: он должен завершить операцию техническим отказом, сохранив прежний результат.
Завершение процесса из-за нехватки памяти невозможно гарантированно перехватить.
Большие строки вызывающий слой должен обрабатывать вне render, например в Worker;
асинхронный контроллер и UI в этот чистый модуль не входят.

## Основания переводов

`QuantityBasis` — разрешённая доменная проекция основания с точными версиями
продукта/состояния. Для штуки обязательно совпадение конкретного основания.
Для г/кг и мл/л при том же продукте и состоянии экспериментальный коэффициент не нужен.
`convertUnit` — низкоуровневая числовая операция; физические записи переводить через
`convertQuantity`, а не по одному названию единицы.

`Conversion` — разрешённая проекция каталожного коэффициента. `ConversionStep`
задаёт выбранное направление и отдельное подтверждение применимости условий и
именно этого направления со ссылками на доказательства. Обратное использование
плотности/массы штуки явно задаётся `direction: 'reverse'`; наличие прямого
коэффициента само по себе его не разрешает. Числовой `fromRange`, если есть,
проверяется на исходном основании коэффициента даже при обратном использовании.
Для смены состояния требуется методика. Коэффициент не применяется между разными
продуктами, к иной версии основания или иной конкретной штуке.

Успех — `available` с новой величиной, исходной записью и выбранными шагами;
отказ — `unavailable` с `original` и причиной `CONVERSION_MISSING` либо
`STOCK_STATE_INCOMPATIBLE`. Исходная запись не изменяется. Невалидная/неполная
цепочка не даёт частичного результата. Поиск пути, разрешение конфликтующих
свидетельств и полная проверка ссылок каталога принадлежат загрузчику/владельцу
основания: они должны оставить неподтверждённый шаг `unconfirmed`, а не выбирать
удобный путь. Никакого автоматического предположения 1 мл = 1 г нет.

## Исходный рецепт и представление

`RecipeScaleSource` — числовая проекция проверяемого источника, не полный RecipeDTO.
Собственное B должно быть положительной конечной дробью с подтверждением и смыслом
порции. `inputBasis` различает весь рецепт и одну исходную порцию. Фабрика сохраняет
неизменяемый снимок источника и явный `normalizationFactor`; у результата есть
ссылка `baseline`. Повторный масштаб принимает только `RecipeBaseline`, а не
предыдущий `ScaledRecipe`. H — целое 1…10; M — абсолютное 1/2, 1 или 2 (для S1 — 1).
Дневных целей, бюджета, потребности и покупок здесь нет.

Время и границы его применимости переносятся без арифметического масштабирования.
Наличие `timeEvidence` в результате само по себе не означает, что время применимо
при новом масштабе: это отдельная проверка будущего допуска рецепта.

Представление использует запятую, пробелы тысяч и знак `−`. Количества не содержат
конечных нулей, положительные значения меньше экранного шага показываются через `<`.
Деньги/ккал/БЖУ имеют соответственно 2/0/1 знаков. Отрицательного нуля нет.
`formatMoneySum` форматирует уже рассчитанные строки, складывая точные числа;
при расхождении с суммой показанных строк возвращает обязательное пояснение.
Строки представления никогда не передаются обратно в расчёт.
